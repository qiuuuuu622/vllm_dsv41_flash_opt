# W4A16 → W4A8 + 输出后处理融合：已测性能

实验日期：2026-11-01。此表从既有原始 JSON 重新计算，没有重新运行 GPU 实验。

## 范围与计时

官方 vLLM 0.32.0（基线 commit `5df63a7203cdb9328d824a27b682e77c7b9928be`）、Humming 0.1.17、torch 2.13.0。两张 H20 分别独立测逻辑 EP8 rank 0/1，每卡 48 个完整专家，H=5120、I=2304、全局 E=384、top-k=6。

计时包括输入整理、量化、W13、SwiGLU/W2 输入处理、W2、逆排列/加权和、乘 routed scale=1.5、加已就绪的 shared partial。不包括 router/shared GEMM、八卡通信、attention 和完整服务。

A16 和 A8 是分开运行的测试组，使用固定种子和相同形状/路由。每组的 base/tiled/fused 交替测量：每个 CUDA Graph 含 20 次调用，9 轮回放取中位数。编译及权重准备不计时。GEMM 保留默认启发式及原来的 Stream-K 配置。

## 保守适配器与完整融合的区别

自动适配器只替换小 token 输出 kernel，不融合 scale/shared。单独测得 rank 0：T=8 从 83.87 降至 82.28 µs（约 1.91%），T=128 从 353.18 降至 348.18 µs（约 1.42%）。T=512/2048 使用原版 kernel，微小差异是测量波动。不能把上表融合收益标到这个适配器上。

完整融合是 shared partial 已就绪的局部实验，尚未接入完整 MoERunner 共享专家调度/DBO/EP collective，不能当作整服务收益。
